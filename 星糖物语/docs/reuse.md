# 复用指南

## 最容易复用的部分

`src/engine.js` 中 `CandyEngine` 负责棋盘生成、合法交换、匹配与特殊糖、结算掉落、检测可走步和重排。`src/elements.js` 的 `ElementSystem` 在其上加入元素反应。两者使用普通 JavaScript，没有 npm 依赖，但当前以浏览器全局类方式组织。

新项目可先抽取棋盘层，自己提供 UI 和素材。它目前固定为 7×7 棋盘，部分边界计算也写死为 49 格；改变尺寸时需要系统修改并重新测试。特殊糖、元素反应与分数规则存在星糖物语自己的设计，复用前应逐项选择。

## 需要解耦的部分

- `appScript.js` 是整场游戏的集成层，依赖大量现有 DOM、全局状态与插入占位符，不适合作为独立库直接引入。
- 关卡、收藏、小屋故事与角色表现是本作内容。复制机制不需要复制这些内容。
- `save-store.js` 处理真实玩家进度、备份和冲突；变更字段时要检查已有存档，不能只改默认值。
- 广告、榜单与云存档接口依赖 TapTap 容器和原项目标识。其他平台请重新实现适配，并核对实际回调。
- `scripts/` 保留了从早期版本演化来的工具。新游戏不需要把全部历史脚本带走。

## 建议的最小抽取

1. 将 `CandyEngine` 复制到独立模块，先把棋盘尺寸、元素池、随机数源变成显式参数。
2. 写一个只画棋盘与交换结果的小页面，验证无初始三连、有多个可选动作、重排可继续游玩。
3. 需要元素反应时再加入 `ElementSystem` 和相应效果定义，保持预览与实际结算规则一致。
4. 最后加入关卡、存档、经济和渠道接口。每层都通过明确输入输出连接，避免继续依赖页面全局变量。

这些是迁移建议，不表示本仓库已经完成上述模块化改造。
